NIM Agent — Documentation for Website
=====================================

A brief overview of the NIM Agent, its features, and capabilities. This document is
intended for use on a website or marketing page.


1. Overview
-----------

NIM Agent is an AI-powered browser extension that automates web research, interaction,
and data extraction. It runs entirely on the user's device as a side-panel extension
for Chrome/Edge, with no backend servers owned by the developer.

It is "powered by NVIDIA NIM and any OpenAI-compatible provider" — users can connect
their own API keys for NVIDIA NIM (cloud or self-hosted), OpenAI, Google Gemini,
Groq, Ollama (local), or any custom OpenAI-format endpoint.


2. Core Architecture
--------------------

- Browser Extension (Manifest V3): Built on WXT (WebExtension tooling framework)
  using React, TypeScript, and Vite.
- Three-tier messaging: Port-based streaming between side panel and background
  service worker, runtime messages for control signals (start/stop/resume), and
  Zod-validated protocol schemas for message integrity.
- Side panel UI with 6 tabs: Chat & Control, Reasoning Trace, Tasks & Macros,
  Research Notes, Security Log, and Settings.
- Keyboard shortcut: Alt + Shift + N opens the side panel. Omnibox keyword: "nim".


3. How It Works (ReAct Loop)
-----------------------------

NIM Agent uses a ReAct-style agent loop:

  1. Intent Classification — classifies the user request as "chat" (no tools) or
     "agent" (tools enabled) before the first LLM call, saving tokens.
  2. Think — the LLM reasons about the current state and available tools.
  3. Act — the LLM emits a tool call (navigate, click, search, read, etc.).
  4. Observe — the tool executes in the browser and the result feeds back to the LLM.
  5. Repeat — the loop continues until the task is complete or max iterations is reached.

The engine supports streaming responses, adaptive context compression, checkpoints
for interrupted tasks (pause/resume), and a final-answer synthesizer that cleans up
output into readable markdown.


4. Browser Automation Tools
---------------------------

NIM Agent exposes 16 function-calling tools for web browsing and automation:

  - web_search        — Live web search via Brave Search API or Serper (Google).
  - read_page         — Extract visible text, links, and interactive elements
                         tagged with numeric IDs (Set-of-Marks indexing) for
                         precise targeting.
  - navigate_to       — Navigate the active tab or open a new tab to any URL.
  - click_element     — Click buttons, links, checkboxes, radios, etc. by numeric
                         ID, CSS selector, or semantic label.
  - type_text         — Type into input fields or contenteditable areas by ID
                         or selector.
  - select_option     — Select an option in a <select> dropdown or combobox.
  - press_key         — Send keyboard events (Enter, Tab, Escape, arrows).
  - wait_for          — Wait for a CSS selector to appear or disappear.
  - scroll_page       — Scroll up, down, or to a specific element.
  - screenshot        — Capture a viewport screenshot (opt-in).
  - summarize         — Summarize page content and save findings to Research Notes.
  - list_tabs         — List all open browser tabs with titles and URLs.
  - switch_tab        — Switch the active tab by ID or URL keyword.
  - close_tab         — Close a tab by ID or the current active tab.
  - extract_table     — Extract structured table or card data as JSON and CSV.
  - parallel_research — Spawn parallel worker sub-agents across multiple
                         background tabs simultaneously (see below).

All tool calls are validated against Zod schemas before execution, and the engine
only attaches tools to the LLM when the model reports tool support.


5. Parallel Sub-Agents
----------------------

The parallel_research tool enables concurrent multi-tab research. The agent spawns
up to 5 worker sub-agents in background tabs that run simultaneously:

  - Extract mode: Fast static scraping — reads page text, extracts tables,
    sanitizes content, and summarizes with a worker LLM.
  - Interact mode: Full agentic loop — the worker can click, type, scroll, and
    navigate within the locked domain to fill forms or collect paginated data.
  - Domain locking: Workers are confined to the initial hostname (cannot navigate
    to external sites).
  - Tool allowlisting: Sub-agents only receive a restricted set of tools.
  - Separate worker config: Users can configure a secondary API key/provider
    (e.g., a cheaper or faster model) for sub-agent work.
  - Auto-cleanup: Background tabs created by workers are closed after completion.


6. Multimodal & Vision Support
------------------------------

  - DOM-first policy: Page structure is extracted from the live DOM before any
    visual analysis. The agent indexes interactive elements with numeric IDs.
  - Vision fallback: Screenshots are triggered only when:
      - The user explicitly opts in (per task), OR
      - DOM content is sparse (< 200 characters), OR
      - DOM extraction has failed twice consecutively.
    The LLM cannot bypass this gate — it is enforced in the execution layer.
  - Opt-in only: No screenshots are taken in the background or without user
    initiation.


7. Model Flexibility
--------------------

  - Live model discovery: Queries the provider's /v1/models endpoint to enumerate
    available models. No hardcoded model IDs. Filters out embeddings, rerankers,
    vision encoders, and other non-chat models automatically.
  - Capability inference: Models are auto-tagged for tool support, vision support,
    agent-tuning, and context-window length based on heuristics, live probing,
    and provider metadata.
  - Provider presets include:
      - NVIDIA NIM (cloud): integrate.api.nvidia.com
      - NVIDIA NIM (self-hosted/local): localhost:8000
      - Google AI Studio (Gemini API)
      - OpenAI
      - Groq (fast inference)
      - Ollama (local, private)
      - Custom endpoint: any OpenAI-compatible base URL.
  - Auto-fallback: If a model reports it doesn't support tools, the engine
    retries the request without tools so the task can continue.


8. Security & Privacy
---------------------

NIM Agent is designed with a layered security model:

  a) API Key Storage
     - Keys are stored in Chrome's extension storage sandbox (.local), which is
       persisted across browser restarts but inaccessible to websites and other
       extensions.
     - No developer backend servers exist. All LLM requests go directly from the
       browser to the user-configured provider.

  b) Prompt Injection Defense (Quarantine Layer)
     - Before page content is passed to the main agent, it is routed through a
       dedicated extraction-only LLM call that strips instruction-like text,
       ignores "ignore previous instructions" payloads, and flags injection
       attempts. Detected injections are blocked and logged.

  c) Destructive Action Protection
     - Keywords like submit, delete, purchase, buy, send, pay, checkout, etc.
       trigger a Human-in-the-Loop (HITL) confirmation prompt. The user must
       approve before the action executes.

  d) Sensitive Field Blocking
     - The agent refuses to type into fields matching password, credit card,
       SSN, CVV, OTP, 2FA, and 35+ other sensitive patterns. This is enforced
       both at the action-validation layer and inside the DOM execution script.

  e) Domain Scoping
     - Sub-agents are domain-locked to their starting URL. The main agent warns
       on out-of-scope navigation and can prompt for approval.

  f) Sender Authenticity
     - The background service worker rejects messages from foreign extensions,
       validated by checking sender.id against the extension's own runtime ID.

  g) Schema Validation
     - All tool calls are validated with Zod before execution. Malformed calls
       are logged to the security audit log and rejected.

  h) Security Audit Log
     - The Security Log tab records injection attempts, blocked actions,
       out-of-scope domains, sender rejections, schema errors, and budget
       ceiling hits. Entries auto-expire after 7 days.


9. Cost Control & Budget Limits
-------------------------------

  - Hard ceilings: Per-task token limit, daily token limit, and daily USD
    spending cap (all user-configurable with sensible defaults).
  - Budget guard: Before each LLM call, the engine estimates token cost and
    checks against limits. When exceeded, the agent pauses (not crashes) and
    prompts the user to approve an override or stop.
  - Live cost display: The side panel shows real-time token usage and estimated
    cost per task and per day.
  - Worker cost tracking: Parallel sub-agent usage is also counted against the
    same budgets.


10. Resilience & State Management
--------------------------------

  - Checkpoints: The agent saves a full transcript checkpoint (including the
    LLM conversation history and action log) before every iteration. If the
    browser crashes, the tab closes, or the user stops, the task can be resumed.
  - Interrupted task recovery: On browser startup or worker wake, the extension
    scans for paused/running checkpoints and surfaces them in the Tasks tab.
  - Adaptive context compression: When the conversation approaches 80% of the
    model's context window, older turns are summarized into compact
    representations. Key findings, system messages, and the original task
    instruction are never compressed. Atomic turn grouping ensures tool_call
    pairings are never broken.
  - DOM self-heal: After every click, type, or scroll, the engine automatically
    re-snapshots interactive elements so subsequent references stay valid.
  - Ephemeral state pruning: Older DOM snapshots in the transcript are pruned
    to prevent token explosion during long sessions.
  - API retry with backoff: LLM API calls use exponential backoff (up to 3
    retries) for transient failures.


11. User Interface (Side Panel)
-------------------------------

The side panel hosts six tabs:

  Chat & Control:
    - Conversational input with optional vision toggle.
    - Live agent step cards showing reasoning, tool call, and result in an
      animated timeline.
    - Real-time cost bar (tokens + USD).
    - HITL approval banners that appear inline for risky actions.
    - Stop/pause button during execution.

  Reasoning Trace:
    - Full step-by-step execution log with expandable reasoning, arguments,
      and observations.
    - Save any completed run as a reusable Macro (see below).

  Tasks & Macros:
    - History of completed/paused/errored tasks with one-click resume.
    - Saved macros — previously recorded action sequences that can be replayed
      directly without re-planning. Macros can be deleted and show run counts.

  Research Notes:
    - Accumulated summaries and findings from research sessions.
    - Export all notes to clipboard, or clear individually.

  Security Log:
    - Chronological record of all security events with details.
    - Clear-all control.

  Settings:
    - Provider selection (NVIDIA NIM, OpenAI, Gemini, Groq, Ollama, Custom).
    - API key configuration (primary LLM key, optional search API key,
      optional secondary worker key).
    - Live model discovery with capability badges (context size, tools, vision).
    - Cost ceiling configuration and daily counter reset.


12. First-Run Experience
------------------------

On first launch, users see a transparent privacy disclosure explaining:

  - Zero developer backend servers (all traffic goes directly to the
    user's chosen provider).
  - Local key storage model (sandboxed Chrome extension storage).
  - On-demand DOM and vision processing (nothing is captured without
    active user initiation).

Users must acknowledge before proceeding to settings.


13. Data Storage & Lifecycle
----------------------------

  - All data is stored in Chrome's extension-local storage (chrome.storage.local).
  - API keys persist across browser restarts (sandboxed per extension).
  - Task history is capped at 50 entries and pruned after 7 days.
  - Research notes are capped at 50 entries.
  - Macros are capped at 30 entries.
  - Security audit log is capped at 200 entries, TTL 7 days.
  - Checkpoints are deleted upon successful task completion.


14. Technical Highlights
------------------------

  - Manifest V3 extension using WXT framework.
  - TypeScript throughout with Zod schema validation for tool calls and
    inter-extension messages.
  - Streaming support: The engine broadcasts structured step events to the
    side panel in real time, enabling live animated UI updates.
  - Keepalive heartbeat: The side panel sends a heartbeat every 10 seconds to
    keep the service worker alive during long-running tasks.
  - Intent classification before first LLM call (chat vs. agent mode) to
    minimize token usage on conversational messages.
  - Inline JSON recovery: If the LLM emits tool calls as inline JSON or
    plain-text commands (e.g., "navigate_to: https://..."), the engine parses
    and validates them automatically.
  - Multimodal content support: Vision results are passed back as structured
    ContentPart[] (text + image_url) for models that support vision.
  - Background tab wake-up: Synthetic visibility/resize/scroll events are
    dispatched to background tabs to unstick SPAs that pause when not visible.
